# Spike D: 规则确定性检查原型

## 目标

验证关键规则可脱离 LLM 用确定性代码检查（claims/abstract/terms/figures/noise）。

## 结果

用定稿 10 条权利要求 + 摘要实测：

| 规则 | 结果 |
|------|------|
| UM-CLAIM-IND-001 独立权利要求唯一且产品型 | PASS |
| CLAIM-REF-001 引用存在且在前 | 20/20 PASS |
| CLAIM-REF-002 多项从属不得作为另一项多项从属的引用基础 | PASS（修正后） |
| COM-SECT-002 摘要 ≤ 300 字 | PASS（294） |
| COM-TERM-001 术语一致 | PASS |
| COM-REF-001/002 附图标记、图号 | PASS |
| COM-NOISE-001 无宣传语/页脚噪声 | PASS |

**32 项检查全 PASS**。

## 关键教训

1. 规则必须精确表达：初版把"多项引用"误写为禁止，实际指南要求的是"引用多项的从属权利要求不得被另一项多项从属权利要求引用"（即 7 引 6、9 引 8 合法，因为单项引用）。确定性规则写错会误杀合法文件——规则包必须有 fixture 回归测试。
2. 摘要实测 294 字，验证 ≤300 字检查合理。
3. 术语/噪声检查用词表 + 正则即可做第一轮，LLM 复核做第二轮。
