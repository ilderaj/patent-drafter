## Blockers (reproduction required)

1. **Cached provider/model metadata is trusted without validation, and stub metadata names a model that was never called.** In the synthetic probe, a stub run returned `provider: "mock"` and `model: "review-model"` even though the injected provider was not called. On a provider run, changing only a valid cached entry’s `result.meta.provider` and `result.meta.model` to forged strings left its output schema and `outputHash` valid; the next identical run made zero provider calls and returned the forged metadata. `readStoredStage` only checks that these fields are strings (adapter lines 256–270); it does not bind them to the active execution/provider/model or authenticate them (lines 273–314). In addition, a cache hit retains `meta.cached: false`. Fix metadata production and cache validation so V6-17 cannot report a false execution source, model, or cache status. Relevant implementation: `apps/web/src/v6/lib/pipeline-adapter.ts` lines 256–270, 273–314, and 511–527.

   **Reproduction:** Run a stub adapter with `modelId: "review-model"` and target `extract_invention_facts`; inspect the returned stage metadata. Separately run provider mode with a shared cache, alter only the cached stage entry’s `result.meta.provider` and `.model`, then run the same input through a new adapter using that cache. The cache hit returns those altered values without calling the provider.

2. **A malformed cache record cannot be evicted or replaced, so every retry repeats the provider call.** In the synthetic probe, changing a cached stage’s `outputHash` to an invalid digest made the adapter reject the record and run the provider once, so it did not trust the malformed output. However, the cache seam only offers `putIfAbsent`; the corrupt entry remains the first value. Repeating the same input through a new adapter repeats the provider call again, with no repair path. This leaves a permanently poisoned key in any durable cache and can repeat billable or externally visible work. Add a way to quarantine/remove a rejected entry or safely replace it before retrying the provider. Relevant implementation: cache interface lines 38–43, `run` lines 408–418, and `executeStage` lines 537–549.

   **Reproduction:** Run once with a shared cache, change the stored `extract_invention_facts` entry’s `outputHash` to 64 zeroes, and run the same context twice through new adapters over that cache. Each run makes one new provider call because `putIfAbsent` retains the malformed entry.
