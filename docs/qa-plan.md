# QA 计划

## 1. 安全验收（12 项，全部必须有证据）

| # | 验收项 | 证据方式 |
|---|--------|----------|
| 1 | Key 不出现在浏览器存储 | DevTools 检查 localStorage/sessionStorage/indexedDB + 代码审计 |
| 2 | Key 不出现在浏览器发往 vibing.paymond.me 的请求 | 网络面板抓包 + 代码审计 |
| 3 | Key 不出现在 Worker | Worker 源码审计 + 部署后响应抓包 |
| 4 | 专利文件不经过 Worker | 网络面板（仅静态资源） + 审计 |
| 5 | Bridge 只绑定 Loopback | `lsof -i` + 配置审计（127.0.0.1 only） |
| 6 | CORS 不使用 `*` | Bridge 配置审计 + 恶意 Origin 请求测试 |
| 7 | session token 有过期时间 | 代码审计 + 过期后访问测试 |
| 8 | 每次模型发送可以预览 | UI 测试：发送前显示将发送内容摘要 |
| 9 | 日志不含正文 | 日志审计 + 敏感词扫描（正文片段/Key 模式） |
| 10 | Prompt Injection 测试通过 | 恶意材料测试集（材料内注入指令），断言输出不受控 |
| 11 | 恶意附件测试通过 | ZIP bomb/超大文件/路径穿越/宏/恶意 HTML 测试集 |
| 12 | CI 使用 Mock Provider，无真实 Key | CI 配置审计 + 测试运行 |

## 2. Baseline 验收（交底 → 草案包）

### 2.1 识别能力（交底中应识别 ≥8 类问题）

| 问题 | 期望识别 |
|------|----------|
| 保护主题在系统和产品间摇摆 | fact_conflict(subject_swing) |
| NB/470/蓝牙冲突混杂 | fact_conflict(scheme_contradiction) |
| 摘要混入不适当内容 | noise_suspect → 摘要过滤 |
| 电表网关/产品宣传噪声 | noise_suspect → 剔除 |
| 技术问题/特征/效果需重映射 | readiness 报告 + 映射建议 |
| 实用新型需要产品结构和附图 | strategy 建议产品型 + 附图任务 |
| 参数和结构需确认来源 | unsupported → intake 问询 |

### 2.2 生成能力（intake 后）

- 清晰标题（无括注摇摆）
- 产品型独立权利要求 + 合理从属树
- 与权利要求一致的说明书（五段式）
- 摘要（≤300 字）
- 附图任务与标记表
- 支持矩阵（每条特征有来源）
- 风险报告（unsupported/冲突/需确认项）

### 2.3 对账（vs 定稿）

- 结构完整；核心技术特征保留（三模通信/蓝牙mesh/470/网关上行/射频卡）
- 支持关系成立；章节完整；术语与附图一致
- 无依据内容数量 = 0
- 不要求逐字复刻定稿

## 3. 功能验收

| 模块 | 用例 |
|------|------|
| 上传解析 | DOC/DOCX/PDF/扫描 PDF/图片/TXT/Markdown 多附件；解析失败态 |
| Intake | 缺失项/矛盾项/参数来源问询；跳过与必答 |
| 起草 | 18 阶段管线；取消；缓存；版本化元数据 |
| 附图 | FigureSpec 确认；自动生成（框图/流程图）；Drawing Brief（机械图） |
| 审校 | 支持矩阵/一致性/形式规则三审计 |
| 导出 | 摘要/权利要求书/说明书/摘要附图/说明书附图/草案合集/审阅报告/.patentpack |
| 历史 | 快照回溯；导入导出 |
| 设置 | Bridge 配对/Key 管理/删除数据/临时会话 |
| 状态 | 无 Bridge/断连/解析失败/模型失败/离线/Key 失效 |

## 4. 设计验收（.pen → 实现）

- 逐屏比对浏览器截图与 .pen（无显著偏差）
- 响应式：桌面/笔记本/移动关键视图
- 可访问性：键盘导航、焦点管理

## 5. 性能

- 解析大文件（>50MB）异步化；OCR 进度可见
- 首屏加载：静态资源 < 1MB gzip（不含字体）
