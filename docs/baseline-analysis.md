# Baseline 分析：交底 vs 成功提交定稿

> 依据：`fixtures/private/jiaodi-shared-hot-water-meter-2022.12.14.doc`（技术交底，2022-12-14，冯立平）与 `fixtures/private/final-shared-hot-water-meter-2023.10.27.doc`（定稿，2023-10-27，成功提交）。
> 用途：作为起草管线（fact extraction → intake → strategy → claims → spec → figures → audit）的结构、文本规范与对账验收 baseline。

## 1. 定稿结构拆解（对账目标）

### 1.3 定稿的"净化"证据

对比交底，定稿完成了以下治理（每条都是我们管线必须自动化的能力）：

1. **主题统一**：交底在"系统"（权利要求1：系统+后台/云/远程/室内防护）与"产品"（热水表本体）间摇摆；定稿统一为产品型独立权利要求。
2. **制式收敛**：交底中蓝牙/470 双模之外还混入 NB-IOT、CAT.1、485、电表网关内容；定稿收敛为 射频卡 + 蓝牙mesh + 470 三模，删除 NB/电表相关内容。
3. **噪声剔除**：交底包含宣传语（"流畅外观设计，尽显流行时尚"）、页脚噪声（"100004/2011.2"）、国家电网电表规格（USB ≤300mA、掉电上报）等；定稿全部剔除。
4. **问题-特征-效果重映射**：交底的问题分散且与特征混杂；定稿建立"单模依赖网络/实时性差 → 三模互补通信 → 数据准确性更高"的对应链。
5. **权利要求支持关系**：定稿每条特征都能在具体实施方式中找到对应段落；结构类特征（4/5/6/7/8/9/10）在实施例中有描述。
6. **附图一致**：定稿 6 图与附图说明一一对应；附图标记统一为"1、热水表本体"（交底中编号混乱：远程控制器10、智能网关1 与权利要求编号冲突）。
7. **摘要净化**：交底摘要含宣传与噪声；定稿摘要为 300 字内的标准公开式摘要。

## 3. Intake 后应能生成的验收产物

以原交底为输入，管线完成 intake 后应产出（与定稿对比，不逐字复刻）：

1. 清晰标题：一种基于三模通讯的共享热水表（无括注、无"系统"后缀摇摆）。
2. 产品型独立权利要求（交底中结构特征映射到本体+控制主板+三模块）。
3. 合理从属权利要求树（网关→结构→尺寸→固定→插卡→阀门，引用关系合法）。
4. 与权利要求一致的说明书（五段式、特征一一对应）。
5. 标准摘要（≤300 字，无宣传语与噪声）。
6. 附图任务与标记表（图1-6 类型建议 + 附图标记映射）。
7. 支持矩阵（每条权利要求特征 ↔ 交底来源/用户确认）。
8. 风险报告（unsupported 项、冲突项、需人工确认项）。

## 4. 对账判定标准

- 结构：章节完整（五段式 + 摘要 + 权利要求 + 附图）。
- 核心技术特征：三模通信、蓝牙mesh 自组网、470 组网、网关上行 WiFi/4G、射频卡交互 必须保留。
- 支持关系：每条权利要求特征均有 source_backed 或 user_confirmed 来源。
- 术语与附图一致性：附图标记双向一致、图号一致、术语唯一。
- 无依据内容数量：最终导出的 unsupported 内容必须为零。

## 5. 对管线设计的启示

1. **冲突检测必须在起草前完成**：制式冲突（NB vs 蓝牙/470）、主题摇摆是交底最常见问题，应作为 `detect_conflicts` 阶段的硬性 gate。
2. **噪声分离需要确定性规则辅助**：页脚/模板残留（"100004/2011.2"）、宣传句式（"彻底""尽显"）、外部领域关键词（电表/CAT.1/485）可通过规则包做第一轮过滤，LLM 复核。
3. **unsupported 门禁**：定稿中的水通路、手动阀门证明"最终提交文件可能包含交底外内容"——生成器绝不能自动补写，必须走 intake 确认。
4. **附图标记统一**：交底编号混乱是高频缺陷，管线应在 FigureSpec 阶段生成唯一标记表并贯穿权利要求/说明书/附图三端。
5. **有益效果降级**：宣传式断言应降级为"由技术特征支持的效果"，无支持的效果进入风险报告而非正文。
