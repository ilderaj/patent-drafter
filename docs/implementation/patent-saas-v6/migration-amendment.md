# D-V6-07-01：旧本地迁移的分阶段合同

状态：编排者裁决，2026-10-31。迁移合同版本：`legacy-import.v2`，替代 V6-07 初始实现的隐式 v1；持久实体和命令信封仍为 `v6.1`，本次不改变其字段或含义。

## 触发原因与适用范围

V6-06 仅持久化 Matter、Target、Asset、Activity 与字节。旧审阅缺少可验证身份和完整 SnapshotRef，不能伪造 Confirmation 来满足迁移数量。V6-07 独立复核指出，仅在回执中声明延后不足以界定合同。

本文件是当前实施分支的迁移合同补充，限定 01-architecture §8、S08「恢复包与导入」、S13-A09 及 V6-07/V6-26/V6-47a 的分阶段语义。主 checkout 的准备包保持只读。本补充与准备包一起审阅；补充尚未经独立接受时，V6-07 仍是 candidate。

## 旧行为与新行为

原要求「迁移后创建 legacy_unverified 审阅记录」在完整迁移结束时仍必须满足。Foundation 的 V6-07 只复制可校验的案件与图稿，返回包含全部旧审阅及未迁移工作计数的报告；旧审阅在报告中标为 legacy_unverified，正文继续保存在原库。报告不是持久审阅记录，不能将该阶段称为完整迁移。

导入必须经用户确认，原库始终保留。重复导入不得新增重复案件、字节或事件。报告只使用位置引用、计数和固定错误码，不复制不可信 ID 或异常消息。每个资产引用独立验证，重复 ID 不得掩盖冲突；图稿须符合共享合同的 MIME、魔数、大小和像素预算。

## 明确的后续责任与发布门禁

V6-26 负责在恢复包与本地存储可容纳完整修订、图集和审阅历史后，完成旧审阅的持久导入。必须保留旧身份的未验证状态，不能由历史记录生成当前 Confirmation、Approval、使用权或分享授权。无法映射的历史快照保存为明确的未绑定历史，不虚构新快照。该票实施前由编排者扩展持久合同、递增共享 contractVersion，并迁移与回归消费者。

V6-26 新增验收：

- V6-26-M01：含旧外部审阅、本人审阅和缺失快照的合成案件经确认导入，刷新后仍可查看全部历史，身份均为 legacy_unverified；无法绑定的快照明确显示未绑定。
- V6-26-M02：重复导入不增加历史记录；生成的当前确认、批准、授权数量均为零。
- V6-26-M03：原库、未迁移工作和原字节保持不变；导入报告与恢复包列明未转换项；失败重试后与持久状态一致。

V6-47a 必须核对这三项和 S08-A06/A07。全部通过前，禁止删除旧库、关闭旧入口或宣称 R1 迁移完整。V6-08 的可见路由骨架不解除此门禁，不能据此发布完整 R1 产品。

## 本票新增验收

V6-07-M01：assetHash 缺字节、仅在草稿快照引用的资产、图元数据与历史、figureBrief、孤立资产以及畸形集合均有明确报告。

V6-07-M02：同 ID 不同摘要或元数据、长度不符、伪造 MIME、超预算和损坏图片不会成为可用图稿。

V6-07-M03：ASCII 正文伪装的 ID 和存储异常正文不进入报告或导入结果；报告采用位置引用。

V6-07-M04：回执准确区分本阶段导入和完整迁移；V6-26 与 V6-47a 的未完成门禁在发布检查中保持阻断。
