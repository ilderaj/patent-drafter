## G2：材料变化后旧 job retry

| 检查 | 结果 | 事实 |
|---|---|---|
| 先造一个失败作业（429） | pass | `data-job-state=failed` |
| 新增第二份材料并解析 | pass | parse rows=1、已解析 |
| 外发清单确实变化 | pass | `payloadManifestHash` f07e6b0827b7 → dce500488688 |
| 变更后重新确认 | pass | 弹层确认成功 |
| 点旧 job 的「重试为新任务」 | **未得到 INPUT_STALE** | 既无 `generation-action-error`，也没有「新建任务」；弹层被重新打开（sheet=True），runtime 仍为 real |
| 重试期间 chat 增量 | pass（0） | chat 2 → 2 |

另一次尝试把变更换成「确认一条合成事实」（同样改变清单哈希 835b66e8 → ee024f22），结果相同：重试走**重新确认**路径。

源码对照：`generation.ts` `retry()` 用
`previousInput.sourceVersion / targetConfigVersion / figureRevisionId / baseDraftRevisionId` 判断 `materialMoved`；
不满足时返回 `CONSENT_REQUIRED`（「外发授权已变化，请重新确认后再重试。」）。本轮清单哈希已变，但
`currentInput().sourceVersion` 未变，因此进入重新确认分支，而不是 `INPUT_STALE`。

**结论**：G2 判 **blocked**。目前行为是「新增材料/确认事实会改变外发清单并要求重新确认」，但没有触发
`INPUT_STALE`；这是「材料变更是否应推进生成输入的 sourceVersion」的产品口径问题，需开发侧确认，
不是脚本能改的。未出现自动授权或自动发送。
