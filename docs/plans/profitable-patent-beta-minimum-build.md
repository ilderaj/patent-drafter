## 1. Outcome

在首笔收款前，用最小投入证明“中国专利申请准备包”可以被可靠交付；随后运行一个 21 天、最多 5 个付费 Case 的 concierge Beta，验证真实需求、交付质量和至少 40% 的贡献毛利。

Beta 不是完整 SaaS。成功标准不是注册量或 MRR，而是：真实付款、按 SLA 交付、单位经济成立，以及代理人能够继续复核。

## 2. Frozen Product Contract

- ICP：90 天内计划发布、众筹或公开演示的海外中文硬件团队。
- 标准商品：US$499“中国专利申请准备包”，发明或实用新型二选一，全额预付。
- 英文加购：US$199，最多增加 2 小时人工。
- 标准 SLA：材料完整并经平台确认、付款到账后 5 个工作日；等待客户补充期间暂停。
- 纠错：14 天内一次，只修正平台错误、遗漏及原材料已有事实。
- 检索上限：最多 10 条查询式、40 个去重专利族、8 篇深度特征对照文献。
- 人工上限：标准 Case 最多 4 小时，按 US$50/小时计入成本。
- 非人工变动成本上限：US$40/Case；贡献毛利率底线：40%。
- 专业边界：平台不提供法律意见、FTO、授权概率，不代表客户向 CNIPA 递交。

任何执行切片若改变以上合同，必须先回到 Owner 决策，不能在实现中自行调整。

## 3. 最小范围

首笔收款前只建设四类能力：

1. 两件历史 Case 的真实检索基准；
2. 五项准入、订单、数据同意与安全交接材料；
3. 首 5 单统一人工时间/成本/质量台账；
4. 人工付款和交付交接操作面。

默认复用现有起草、审校、导出和 `.patentpack` 能力。只有当历史 Case 或完整干跑证明现有产品存在阻断时，才允许做条件式产品改造。

## 4. 明确不建设

- 账户体系、团队协作、订阅、优惠券、免费试用和自动结账；
- 云端 Case 历史、CRM、邮件自动化、SEO、付费广告和完整运营后台；
- 分析仪表盘、自动代理人撮合、代理服务转售和 CNIPA 自动递交；
- 完整多源自动检索平台、依赖网页抓取/XHR/WAF 绕行的生产管线；
- 非专利文献检索、专业制图、工程图重绘和默认完整双语交付。

## 5. 实施阶段

### Phase A — 绑定范围与可复用资产

目标：在任何产品修改前，固定本次 Beta 的范围和现有能力复用清单。

产物：

- 一份 `reuse / adapt / exclude` 矩阵，覆盖 intake、起草、审校、导出、加密包和数据删除；
- 五项准入字段及 Case 状态定义：`screening → ready_for_payment → paid → in_delivery → waiting_customer → delivered → correction → closed → deleted`；
- 标准 Case、英文加购和另行报价工作的边界表。

验收：所有后续工作都能映射到本计划的四类最小能力；无法映射的需求自动排除。

### Phase B — 检索协议与两件历史 Case 基准

目标：证明真实检索管线足以支撑付费承诺。

执行顺序：

1. 固定人工主导协议及检索日志字段：数据库、日期、查询式、命中数、筛选理由、族归并、深读文献、失败/缺口、人工签核。
2. 选择一件已知发明专利 Case 和一件已知实用新型 Case；仅使用可合法处理、适合基准验证的材料。
3. 先试用 FlowLeap；若质量、许可、隐私或价格不通过，切换至审计后的 EPO OPS MCP/薄适配器，并由 PATENTSCOPE、CNIPA、USPTO 官方界面人工补缺。
4. 对两件 Case 各运行一次完整协议，再由相同输入重跑关键查询和族归并，验证可复现性。

硬验收：

- 2/2 Case 找回预先记录的接近现有技术；
- 所有引用来源可打开，并保存检索库、查询日期和公开编号；
- 专利族去重结果正确，无同族文献重复占用 40/8 上限；
- 每件 Case 可生成 10/40/8 上限内的检索报告、特征矩阵、风险层级和限制声明；
- 报告不含授权概率、FTO、法律意见或“穷尽全球”等表述；
- 工具失败时的人工补缺路径可执行且有日志。

停止条件：任一 Case 无法找回已知接近文献、链接不可验证、族归并不可靠或结果不可复现，则禁止收款，先修正协议或更换工具。

### Phase C — Beta 运营包

目标：不用后台系统也能一致地筛选、收款、交付、纠错和删除数据。

最小产物：

- 五项材料准入清单与最多 15 分钟人工确认流程；
- 一页 Beta 订单书草案；
- 数据处理与明确同意声明；
- 加密 `.patentpack` 传输、分通道口令、具名访问、交付和 30 天删除 SOP；
- 人工付款链接/invoice 交接清单；
- 首 5 单统一手工台账；
- Operator runbook，包含 4 小时预算、一次 30 分钟澄清会、5 日 SLA 暂停/恢复和一次纠错流程。

台账至少记录：

- 潜客四项资格与五项材料状态；
- 每阶段开始/结束时间、人工分钟数和责任人；
- 模型、检索、支付、退款准备金等直接成本；
- SLA 起算、暂停、恢复、交付和纠错时间；
- 退款及原因；
- 是否实际转交代理人、是否 P0 整包退回、结构化反馈；
- QA 副本访问和删除时间。

验收：使用一件无真实客户数据的演练 Case，从筛选到删除完整走通；没有依赖口头记忆的步骤。

### Phase D — 条件式最小产品改造

触发条件：只有 Phase B/C 的演练证明现有应用无法完成必要动作时才进入；否则跳过。

允许改造：

- 将客户承诺统一为“中国专利申请准备包”；
- 五项材料预筛和发明/实用新型单路线确认；
- 数据同意门和 Local-first/人工 QA 数据流说明；
- 导入或附加检索日志、特征矩阵和限制声明；
- Beta 导出包中包含申请草案、检索证据、QA 记录和附图简报；
- 操作者可读取必要状态，但不建设通用后台。

工程验收：

- 新行为有针对性自动测试；
- 现有起草、审校、导出、加密和门禁回归全部通过；
- 浏览器网络证据确认原始 Case 未被自动上传；
- 不新增账户、订阅、云端历史、自动邮件或分析仪表盘。

### Phase E — 首笔收款前放行

必须同时满足：

1. Phase B 两件历史 Case 全部通过；
2. Phase C 完整演练通过，标准 Case 演练人工不超过 4 小时，估算非人工成本不超过 US$40；
3. 独立专业人士完成订单书和数据声明的限定审阅，覆盖非法律服务、退款、数据流/保密、代理人与递交责任；修订后冻结版本号；
4. 安全交接和删除流程完成一次演练并留下非内容审计记录；
5. Owner 做最终 go/no-go，另行授权真实外联和收款。

未取得第 5 项明确授权，不得启动 21 天实验。

### Phase F — 21 天 concierge Beta

边界：

- 从第一次定向外联开始计时 21 天；
- 目标触达 20 个同时满足四项资格的潜客；
- 目标获得 5 个真实 US$499 付款；
- 最多 2 个 Case 并发；首 5 单均由创始人本人执行平台 QA；
- 每单使用统一台账，不在实验中临时建设后台或仪表盘。

每单验收：按固定范围交付；SLA、时间、成本、纠错、退款、代理人反馈和删除均有记录。

### Phase G — 证据裁决

只有同时达到以下条件，才创建完整 SaaS 建设计划：

- 5 个真实付款；
- 至少 3 个 Case 按 SLA 交付；
- 首批整体贡献毛利率至少 40%；
- 至少 3 包实际交给代理人，且没有因核心材料缺失被 P0 整包退回。

如果 21 天内未取得 5 个付款：冻结完整 SaaS 建设，访谈未购买者，只允许根据证据修改一个变量，再启动新的限时实验；不得自动延期或边建边卖。

## 6. 建议切片顺序

1. **Slice 1：检索基准协议和历史 Case 选择** — 已于 2026-08-22 Chief accepted（68/68 PASS）。
2. **Slice 2：运行两件历史 Case** — 当前执行；形成可复现证据和工具 go/no-go。
3. **Slice 3：运营文档与手工台账** — 订单、数据、SOP、ledger。
4. **Slice 4：完整干跑** — 从筛选到删除；判定是否需要产品改造。
5. **Slice 5：条件式产品改造** — 只修复干跑发现的阻断点。
6. **Slice 6：专业审阅与最终放行** — 冻结 Beta 文档版本，Owner 再授权外联/收款。

每个切片独立验收；前一切片失败时停止，不预先开展后续建设。
